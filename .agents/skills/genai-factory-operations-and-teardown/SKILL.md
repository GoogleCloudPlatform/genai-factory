# GenAI Factory Operations, Troubleshooting & Teardown

## Overview

Resolves the four most common cross-factory operational and teardown failures across all `genai-factory` blueprints: `gcloud` impersonation quota project rejections, `*.rep.googleapis.com` VPC blackholes, Serverless VPC IP reservation teardown locks, and leftover generated Stage 0 files.

## When to Use

- Running `gcloud`, `bq`, or `uv` commands from `terraform output -raw commands` with `--impersonate-service-account`.
- Debugging timeouts or TLS certificate errors from private Cloud Run / Agent Engine workloads.
- Running `terraform destroy` on `1-apps` and `0-prereqs`.

## Quick Reference — Error to Fix Mapping

| Error / Symptom | Root Cause | Immediate Fix |
| :--- | :--- | :--- |
| `403 Permission 'serviceusage.services.use' denied` on `gcloud` | Local `gcloud` config has `billing/quota_project` set to another project | `export CLOUDSDK_BILLING_QUOTA_PROJECT="<service-project-id>"` |
| Timeout or TLS mismatch on `aiplatform.<eu\|us>.rep.googleapis.com` or `modelarmor.<region>.rep.googleapis.com` | `private.googleapis.com` (`199.36.153.8/30`) does not route `*.rep.googleapis.com` | Provision `google_network_connectivity_regional_endpoint` + Cloud DNS response policy rule for the `.rep.googleapis.com` FQDN |
| `resourceInUseByAnotherResource` (`serverless-ipv4-cloudrun-*`) in `0-prereqs` `terraform destroy` | Cloud Run Direct VPC Egress retains its `/28` subnet reservation for 5–15 minutes after `1-apps` destroy | Wait 5–15 minutes or destroy the service project (`module.projects`) before detaching the Shared VPC subnet |
| `pytest` or `tools/plan_summary.py` fails with remote GCS backend error | `1-apps/providers.tf` and `terraform.auto.tfvars` generated by `0-prereqs` are still on disk | Delete `providers.tf`, `terraform.auto.tfvars`, `.terraform*`, and `terraform.tfstate*` in `1-apps/` and `0-prereqs/` |

## Core Patterns

### 1. Fix `gcloud` Impersonation Quota Project (`403 serviceusage.services.use`)

Before running commands from `terraform output -raw commands`:

```shell
export CLOUDSDK_BILLING_QUOTA_PROJECT="<your-service-project-id>"
# Or clear the local quota project override:
gcloud config unset billing/quota_project
```

### 2. Clean Two-Stage Teardown Sequence

Always set `enable_deletion_protection = false` in `1-apps/terraform.tfvars` and apply it **before** running `terraform destroy`:

```shell
# 1. Disable deletion protection and destroy Stage 1 (1-apps)
cd 1-apps
terraform apply -var="enable_deletion_protection=false" -auto-approve
terraform destroy -var="enable_deletion_protection=false" -auto-approve

# 2. Destroy Stage 0 (0-prereqs)
cd ../0-prereqs
terraform destroy -auto-approve

# 3. Clean up Stage 0 generated files so git status and pytest stay clean
rm -rf ../1-apps/providers.tf ../1-apps/terraform.auto.tfvars ../1-apps/terraform.tfvars \
       ../1-apps/.terraform* ../1-apps/terraform.tfstate* \
       ./terraform.tfvars ./.terraform* ./terraform.tfstate*
```
